# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in this project, please report it responsibly.

### How to Report

1. **Do NOT open a public issue** for security vulnerabilities
2. Email the maintainer directly, or use GitHub's private vulnerability reporting feature
3. Include:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

### What to Expect

- **Acknowledgment**: We will acknowledge receipt within 48 hours
- **Assessment**: We will assess the severity and impact within 7 days
- **Fix**: We aim to release a fix within 30 days for critical issues

### Scope

- Code vulnerabilities in the main codebase
- Dependency vulnerabilities (outdated packages with known CVEs)
- Configuration issues that could lead to security breaches

### Out of Scope

- Issues in third-party dependencies (report to the respective maintainers)
- Social engineering attacks
- Issues that require physical access to the server
